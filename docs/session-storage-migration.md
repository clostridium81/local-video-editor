# IndexedDB 廃止の仕様・検証記録

更新日: 2026-09-08。対象: ローカル作業ツリー。デプロイは未実施。

## 保存方式

- 素材本体は `assetStore.ts` の Map に File/Blob 参照として保持する。取り込み時に全バイトをコピーしたり、IndexedDB・localStorage・Cache Storage・OPFS に素材を書き込んだりしない。
- 動画・画像・音声、録画・録音からの File は共通の素材追加経路を通る。描画・波形・書き出し側の素材取得インターフェースは維持する。
- プロジェクトは JSON 化可能なメタデータのみ。保存・復元は手動 ZIP v1。再読み込み・タブ終了時には素材と編集内容が失われるため、ZIP の保存が必要。
- 素材追加・削除も Undo/Redo に記録する。削除した素材の本体は履歴から復元できる間保持し、現在の作品にも履歴にも参照されなくなったら解放する。Undo 履歴の上限は従来どおり 100 件。
- 新規作成・復元では旧素材参照、Object URL、履歴、選択、内部クリップボード、波形・描画キャッシュを切り替える。同じ ID の ZIP を再度復元した場合もプレビュー・タイムラインを再生成する。
- ZIP 作成は開始時点の素材参照を確保する。素材欠損をスキップして成功扱いにしない。
- ZIP 復元は別の Map で素材を検証し、全件揃ってから反映する。素材欠損・サイズ不一致・重複・不正な参照で失敗しても現在の作品を変更しない。読み込み中に新規作成・別の復元・編集をした場合は古い復元を反映しない。
- ストレージ永続化要求と残量表示は廃止。素材パネルには素材ファイル合計と手動バックアップの案内を表示する。この合計はメモリ使用量の推定値ではない。
- 表示設定とバックアップ済み判定用ハッシュの localStorage 保存は維持する。素材本体・素材名・編集状態を保存する用途には使わない。

## 旧版データの扱い

起動時に `indexedDB.deleteDatabase('local-video-editor')` だけを実行する。DB の新規作成・読み出し・書き込みはしない。削除待ちでアプリ起動を止めず、旧版のタブによるブロック、API 使用不可、削除失敗を通知する。ブロック解除後に削除が完了したら通知を消す。他の DB は削除しない。

この移行コードの実装は、公開済みサイトやユーザーのブラウザ内の旧データがすでに削除されたことを意味しない。更新版の起動時に処理される。旧版を開いたままのタブは旧コードで書き込み可能なので、閉じる必要がある。

同一オリジンの別アプリから残存 IndexedDB の素材を直接読まれる経路をなくす変更であり、XSS や同一オリジンのウィンドウ間アクセスを隔離する変更ではない。File/Blob の内部配置、ブラウザの一時ファイルや OS のスワップ等を制御するものでもない。

## 自動検証

`npm test` は 113 チェック (既存 89 + セッション 18 + 描画接続 6) すべて成功。Pages ビルド前にも実行する。

| 対象 | 確認内容 |
| --- | --- |
| 既存 smoke | キーフレーム、トランジション、履歴、フレーム時刻、エフェクト、バックアップ署名等の既存チェック |
| session: 18 ケース | 実際の Pinia ストア・素材ストア・fflate ZIP 入出力を使用。DOM のメタデータ取得のみ代替 |
| preview/source: 6 ケース | 実際の PreviewEngine と FrameSource を使用。DOM/Canvas は呼び出しを記録する代替 |

セッション検証では、IndexedDB へのアクセスを例外にする状態で素材追加・Undo/Redo・ZIP 保存/復元が成功することを確認する (旧 DB 削除のケースだけ API を差し替え)。

主な確認項目:

- File の同一参照保持、作品 ID ごとの分離、同時 URL 取得、URL 無効化。
- 動画/画像/音声/録画・録音相当の File の登録と読み出し。実録画ではなく生成した File を使用。
- 素材追加/削除の Undo/Redo とクリップ復元。履歴打ち切り・Redo 破棄後の素材解放。
- 新規作成後の素材・URL・履歴・選択・内部クリップボード・バックアップ通知の初期化。
- メタデータ読み込み中の作品切り替え、一括追加の残りのファイルのキャンセル。
- ZIP 往復時の全素材バイト・MIME・編集情報の一致と、従来の v1 配置を独立に組み立てた ZIP の読み込み。
- 不完全 ZIP の拒否と現作品の保持。ZIP 作成中の作品切り替え。素材なしのテキスト作品の保存。
- 旧 DB の指定名だけを削除すること、ブロック後の完了通知、使用不可でも編集が続くこと。
- プレビューの素材 URL、素材削除後の画像再読み込み、非同期読み込み中のエンジン破棄、同じ ID で復元した素材の切り替え。
- 動画書き出しの `<video>` フォールバックがセッション素材を取得し、シーク・終了できること。

`npm run build` による Vue/TypeScript の型チェックと本番ビルドも成功。

## 実ブラウザ確認の残り

この作業環境では Browser の接続先がなく、実画面での操作・実デコード・実録画・実エンコードの確認は未実施。自動テストだけで映像や音の品質に副作用がないとは断言できない。

公開前に次を実ブラウザで確認する:

1. 動画/画像/音声をファイル選択・ドロップで追加し、配置・再生・シーク・波形表示を確認。動画を音声トラックに配置する経路も確認。
2. 使用中の素材を削除して Undo/Redo。同じ ZIP を再復元して、プレビュー・音・波形が復元した素材と一致することを確認。
3. カメラ・画面録画・マイク録音から素材を追加し、再生・ZIP 保存/復元を確認。
4. MP4/WebM/GIF を書き出し、映像・音・尺を変更前と比較。ブラウザ/コーデック別の対応差を確認。
5. 2 タブで別々に編集し、片方の新規作成・再読み込みが他方の素材・ZIP 保存に影響しないことを確認。
6. 隔離したテスト用オリジンに旧 DB を用意し、旧接続を開いたまま起動してブロック通知→接続終了後の削除を確認。削除失敗時も編集できることを確認。

ZIP は引き続き一括圧縮/展開であり、長尺素材・大きな ZIP のメモリ負荷は今回解決したものではない。

## 操作のセキュリティ監査

セキュリティ監査スキルに従った自己監査では、リスク対象操作なし。実施したのはローカルコード・文書の変更、依存削除、テスト、ビルド、ブラウザ接続先の確認のみ。素材の外部送信、ユーザーのブラウザデータの操作、公開、外部へのメッセージ送信は実施していない。自己監査はこの作業の操作記録に基づくもので、アプリ全体の安全性を保証するものではない。
